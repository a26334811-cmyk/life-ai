LIFE AI — 채용공고 찾기 · 지원 관리

기본 경로: 인증키 없는 블로그 RSS + 외부 공고 검색 + 직접 저장
선택 경로: 승인된 사람인 API / 고용24 API
새 기능의 사용법과 검증 절차는 아래 '채용공고 찾기' 항목을 참고하세요.

기존 Q-Net 및 초기 배포 안내

연결 대상
1) 고용24 채용정보 API
   - 실제 회사명, 채용제목, 등록일, 마감일, 지역 등을 가져옵니다.
   - Netlify 환경변수: WORK24_AUTH_KEY

2) 한국산업인력공단 Q-Net 국가자격
   - 국가자격 종목목록에서 사용자가 입력한 자격명을 종목코드로 찾습니다.
   - 국가자격 시험일정 API에서 실제 원서접수/시험/합격발표 일정을 조회합니다.
   - Netlify 환경변수: DATA_GO_KR_SERVICE_KEY

중요
- 인증키를 index.html에 직접 넣지 마세요. 친구에게 링크를 공유하면 노출됩니다.
- 반드시 Netlify 환경변수에 넣습니다.
- 고용24 OPEN API는 기업회원 전용이며 신청/심사 후 인증키가 발급됩니다.
- 공공데이터포털 Q-Net 시험일정은 활용신청 후 인증키가 필요합니다.
- 공식 데이터라도 변경될 수 있으므로 LIFE AI 화면에서 원문 확인 안내를 유지해야 합니다.

Netlify 배포
1. 이 폴더 전체를 Git 저장소 또는 Netlify 배포 대상으로 사용
2. Netlify > Site configuration > Environment variables
3. WORK24_AUTH_KEY, DATA_GO_KR_SERVICE_KEY 등록
4. 새 Deploy 실행
5. 앱에서 취업 목표 → 채용 상세 → '실제 공고 불러오기'
6. 자격증 목표 → 자격증 화면 → '실제 일정 불러오기'

주의: Netlify Drop의 단순 정적 폴더 업로드 방식에서는 Functions 배포가 제한될 수 있습니다.
가장 안정적인 방식은 GitHub 저장소와 Netlify를 연결하여 배포하는 것입니다.

v6.1 Q-Net 수정사항
- 공공데이터포털 화면의 URL 인코딩된 일반 인증키를 환경변수에 그대로 넣어도 되도록 1회 디코딩 처리
- 국가자격 종목 목록 공식 응답 태그(jmcd, jmfldnm, qualgbcd, qualgbnm) 반영
- 국가자격 종목 목록 API 활용신청이 별도로 필요함
- Q-Net 시험일정 공식 HTTPS 요청주소 사용
- API 오류 메시지 표시 개선

필수 활용신청 2개
1. 한국산업인력공단_국가자격 시험일정 조회 서비스
2. 한국산업인력공단_국가자격 종목 목록 정보


v6.2 핵심 수정
- Q-Net 시험일정 JSON 응답에서 body.items를 직접 배열로 읽도록 수정
- 과거/다른 형식의 body.items.item 구조도 호환
- totalCount 진단값 추가
- 인증키/종목코드 변환은 v6.1 방식 유지

정상 테스트 예:
https://<내사이트>.netlify.app/.netlify/functions/qnet-schedule?name=전기기사&year=2026

정상 시 qualification.name = 전기기사, totalCount > 0, items 안에 2026년 회차별 일정이 표시됩니다.

채용공고 찾기 · 인증키 없는 기본 경로
- 취업 관리 → 채용공고 찾기 → 취업왕김백수 블로그 새 글 → 공고 찾기
- 공개 RSS(https://rss.blog.naver.com/dodam852.xml)에서 제목·게시일·원문 링크만 읽습니다.
- 본문·이미지는 복제하지 않으며, 블로그 게시일을 모집 시작일이나 마감일로 사용하지 않습니다.
- 검색은 RSS에 제공된 최근 최대 50건의 제목에만 적용됩니다. 과거 글 전체 검색이나 새 글 알림이 아닙니다.
- 지역 입력은 가져온 결과의 부분일치 필터입니다. 블로그는 제목, API는 근무지역에서 찾습니다.
- 조회 후 '확인 후 관심 공고 저장' → 공식 공고 확인 → 회사명·마감일·공식 URL 확인 후 저장합니다.
- 출처 원문 링크는 공식 공고 링크와 별도로 보존됩니다. 중견 이상 여부·연봉·고용형태는 자동 추정하지 않습니다.
- API 키가 없거나 조회가 실패해도 공식 채용/사람인/잡코리아 검색 링크와 수동 저장을 이용할 수 있습니다.

사람인 승인 후 연결
1. 승인 후 앱을 등록하고 access-key를 발급받습니다.
2. Netlify 환경변수 SARAMIN_ACCESS_KEY에 등록합니다. 저장소나 HTML에는 넣지 않습니다.
3. 환경변수가 적용되도록 다시 배포합니다.
4. 채용공고 찾기에서 사람인을 선택하고 회사명·직무 검색어를 입력합니다.
5. 회사·제목·지역·원문 링크와 모집 마감일을 실제 공고와 대조합니다.
- 사람인 출처 및 Powered by 취업 사람인 링크를 표시합니다.
- 공백으로 나눈 단어는 AND 검색입니다. 과도하게 좁은 검색어 대신 회사 또는 직무부터 검색하세요.
- 응답은 10분 캐시를 사용합니다. Function 인스턴스별 캐시는 재시작 시 사라지므로 일일 호출한도를 보장하지 않습니다.
- 공식 안내 일일 500회 제한을 준수해야 합니다. 공개 다중 사용자 서비스로 확대하기 전 공유 캐시/호출 제한이 필요합니다.
- 현재 실제 승인 키로 사람인 API를 호출하는 검증은 미완료입니다. 공식 명세 기반 모의 응답 검증만 완료합니다.

백업과 복원
- 취업 관리 → 공고·관심 회사 백업에서 JSON 다운로드/불러오기를 사용합니다.
- 관심 회사와 공고(지원상태·준비목록·면접일·출처)를 포함하며, 목표/자격증 데이터는 포함하지 않습니다.
- 불러오기는 기존 기록 유지 + 새 기록 추가입니다. 같은 공고 URL과 공백을 뺀 같은 회사명은 중복 추가하지 않습니다.
- 기존 기록을 최신 백업으로 덮어쓰는 기능은 없습니다. 파일의 형식·날짜·URL·크기를 검사하며 잘못된 백업은 저장하지 않습니다.
- 백업은 암호화하지 않으므로 개인 메모가 포함된 파일은 직접 보관하세요.

개발/검증
- 루트가 배포 원본입니다. 이전 배포본 LIFE_AI_v6_2_QNET_LIVE_FIXED (3)/life_ai_v6_2는 변경하지 않습니다.
- Netlify Base directory는 저장소 루트, Publish directory는 '.', Functions directory는 'netlify/functions'를 사용하세요.
- npm ci
- npm test
- npx playwright install chromium
- npm run test:browser
- 브라우저 테스트는 실제 버튼 클릭·요청·결과 표시·저장·재로드·다운로드·복원을 확인하며 외부 응답은 모의 처리합니다.
- npm ci 후 npx netlify dev로 Functions 포함 로컬 점검을 할 수 있습니다. 정적 서버만으로는 Functions가 실행되지 않습니다.
- 고용24 파서는 정상 XML과 총건수를 확인합니다. 잘린 응답은 빈 검색 결과 대신 오류로 처리합니다.
- 운영 배포 후 blog-jobs의 실제 수신·날짜 표시·원문 링크를 다시 확인하세요. RSS 제공 범위나 제공처 정책 변경으로 연결이 중단될 수 있습니다.
